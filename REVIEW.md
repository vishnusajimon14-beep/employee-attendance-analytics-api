# REVIEW.md

The table below compares the supplied starter `app/main.py` with the implementation built on top of it. The symptoms describe ways the defects can be detected; they are not a claim that every edge case has already been tested.

| # | Where (starter function / area) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It only considers the shift start clock time. It does not account for overnight shifts, and the threshold/rounding needs to follow the specified late-arrival rule. | Test a punch-in just inside and outside the grace period, then test an overnight shift after midnight. | Updated the helper to accept shift start and end, identify overnight shifts, and apply the grace period before returning late minutes. |
| 2 | `compute_work_hours` | Built-in `round()` does not guarantee the assignment's required half-up rounding behavior. | Test a duration that lands on a rounding tie. | Used `Decimal` and `ROUND_HALF_UP` to calculate work hours. |
| 3 | `compute_overtime` | It does not account for overnight shifts and does not apply the required minimum overtime threshold. | Test punch-out times before and after the scheduled end, including an overnight shift and the threshold boundary. | Updated overtime calculation to account for the shift date and overnight end time, and return overtime only when it reaches the required threshold. |
| 4 | `EmployeeIn`, `PunchInIn`, request models | Starter request models accept loosely validated employee fields, shift times, statuses and timestamps. | Send malformed employee codes/emails, invalid times/statuses, or timestamps in seconds instead of milliseconds. | Added Pydantic constraints, allowed status literals, date/time validation and strict epoch-millisecond bounds for punch timestamps. |
| 5 | `health` | The starter returns `{"status": "ok"}` even if MongoDB is unavailable. | Stop MongoDB and call `/health`. | Added a MongoDB ping and return HTTP 503 when MongoDB is unavailable. |
| 6 | `create_employee` | Duplicate prevention relies on a check-then-insert sequence, which can race; it also lacks reliable database-level uniqueness. | Send duplicate employee codes, including concurrent requests. | Added a unique `emp_code` index and handle `DuplicateKeyError` as HTTP 409. |
| 7 | `list_employees` | Pagination skips `page * page_size`, so page 1 skips the first page; the total count ignores the department filter; results are not consistently sorted. | Request page 1 and page 2 with and without a department filter. | Corrected skip to `(page - 1) * page_size`, count using the same filter, sort by `emp_code`, and validate pagination bounds. |
| 8 | `punch_in` | The starter does not return 404 for an unknown employee, uses naive/local timestamps, derives the date without overnight-shift handling, and can expose an internal MongoDB ID. The duplicate check alone is not concurrency-safe. | Punch in for an unknown employee; test an overnight shift after midnight; submit two identical requests concurrently. | Added employee existence validation, IST handling, overnight attendance-date logic, epoch-millisecond response values, a unique compound index on `(emp_code, date)`, and duplicate-key handling for HTTP 409. |
| 9 | `list_attendance` | It loads all matching documents into Python, sorts and paginates in memory, has no inclusive date-order validation, and returns internal IDs instead of the contract response. This will scale poorly. | Query a large collection, use invalid date ranges, or inspect response fields. | Moved filtering, sorting and pagination into MongoDB; added date validation, total count, bounded pagination and timestamp/history serialization. |
| 10 | Missing contract endpoints | The starter leaves punch-out, regularization, monthly employee analytics, department summary, late leaderboard, department trend and explain functionality unimplemented. | Compare routes and behavior with `openapi.yaml`; call each required route. | Implemented the missing endpoints, business-rule calculations, audit history and explain branches in the existing `app/main.py`. |
| 11 | Attendance concurrency and audit history | A read-then-write approach can allow two punch-outs or regularizations to overwrite each other; attendance records need a unique key and regularization history must be preserved. | Send simultaneous punch-outs or edits and inspect the stored history. | Used a conditional update for punch-out, a unique `(emp_code, date)` index for punch-in, and a conditional regularization update that checks the old record values/history and returns HTTP 409 if it changed concurrently. |
| 12 | Analytics and query performance | Analytics and explain endpoints were absent from the starter, so the required aggregation rules and query plans were not implemented. | Compare results for joiners, employees with no logs, weekends, half-days and tied leaderboard ranks; inspect explain output. | Added MongoDB aggregation pipelines for the analytics endpoints and `/admin/explain/{endpoint}`, plus indexes for employee lookups, attendance date filters and sorting. |

## Reviewed and not treated as defects

- `emp_code` is the business identifier; MongoDB `_id` should remain internal. The implementation uses `emp_code` in API paths and responses rather than exposing `_id`.
- A weekday with no attendance record is not the same as an `ABSENT` record. The analytics logic must preserve that distinction rather than automatically inventing attendance records.
- The department trend is intentionally generated in MongoDB using `$documents`/`$densify` so that weekends and dates without logs can still appear. Its root stage is not expected to be a collection `IXSCAN`; index usage should be checked inside its lookups.
